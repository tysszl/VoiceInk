# Phonon review, November 2026

Reviewed [Infatoshi/phonon](https://github.com/Infatoshi/phonon) at `2e9a5b7` (2026-11-05) against this fork at upstream v2.25. Phonon is a GPL macOS dictation app: Parakeet TDT v2 for speech, then a fine-tuned 1.7B local model (the "refiner") that cleans every dictation, both on its own Metal kernels.

**Verdict:** adopt one setting now, build one small tool, and run a few experiments, the main one a fully local cleanup option graded against Cerebras. Phonon's main selling point, speed, comes from its architecture (cleanup runs while you talk, on custom GPU kernels), not from anything VoiceInk can switch on. Most of its other features are already in upstream VoiceInk 2.25.

## Do now

1. **Turn on Smart Punctuation** (Settings, next to the paste method). It is upstream's cursor-aware fix, added 2026-10-25 and off by default. It reads the text around the cursor and fixes the first letter's case, a doubled or stray final period, and spacing so a dictation fits mid-sentence. Phonon's strongest data point backs it: 40 of its author's 44 hand corrections in Wispr Flow (a commercial dictation app) changed only the first letter's case or the final period to fit text already on screen. Phonon has not built this fix; VoiceInk has. It leaves the text unchanged when it cannot read the field, and skips non-ASCII text, newlines, code, and email addresses. Reversible with the same toggle.

2. **Check whether voice detection (VAD) is dropping real speech.** VoiceInk runs Silero VAD at threshold 0.7 before Parakeet. When it finds no speech, VoiceInk skips transcription and returns nothing (`FluidAudioTranscriptionService.swift:195-197`). Phonon found the same failure in its own gate: 13 of 49 clips it rejected held 3 to 28 words of real speech, so it now keeps the transcript whenever the model hears at least 3 words. Your history:
   - Of 14,123 recordings in the stats, 291 ran longer than 1.5 s and came back with no text (2%). Some are accidental holds.
   - On 2026-11-05, an 83-second recording in Cleanup mode returned nothing. It is mostly quiet (mean -51 dB, against -36 to -40 dB for normal dictations) but has a 3.5-second loud span. Six short empty clips that day were 15 to 20 dB quieter than normal, so they are probably silence.
   - The check: transcribe empty recordings again with voice detection off. Recordings are kept for 24 hours (`TranscriptionRetentionMinutes` = 1440). If they come back with words, VAD is losing dictations, and the fix is Phonon's 3-word rule (a small `// Fork tuning:` edit, or an upstream issue).

## Build

3. **A vocabulary finder for your Dictionary** (a script, not app code). Your Dictionary holds 41 words and 20 replacements. VoiceInk uses them in every Mode, not only Cleanup: after transcription it runs its own phonetic matcher (`RecordingVocabulary.correctTranscription`), which fixes a misheard dictionary term without any model. So more good terms also help Raw mode, where most of your dictation goes (56 of 69 today). Your November cleanup eval found the same gap: misheard words not in the Dictionary (Cerebras, Qwen, MacBook) stay as heard.

   Phonon's method, as a script of about 300 lines:
   - Pull the messages you wrote from `~/.claude/projects` (user turns with plain text content, harness lines and long pastes dropped), plus your repo names and your own name as seeds.
   - Keep the tokens that look like terms: CamelCase, ALL CAPS, words with digits, hyphenated or dotted names, capitalized words that are not at a sentence start, and lowercase words not in `/usr/share/dict/words`. Keep only those seen at least twice.
   - The "ASR oracle": speak each candidate with `say` in two voices inside "let's use ___ for this", transcribe it with Parakeet, and keep only terms Parakeet gets wrong. Each wrong output becomes a replacement (heard form to term); case-only misses become vocabulary words. About 0.7 s a term, all on the Mac.
   - You approve the list, then it writes a file in VoiceInk's dictionary import format.

   What Phonon measured: candidates from chat plus code reached 159 of 185 held-out terms from its author's own dictionary; the Opus-picked top 400 found 47% of the terms its author actually used. Its miner never shipped in its app (it is a developer tool), and its local-model filtering step is gitignored. Reimplement it rather than run Phonon's code, which scans your home folder. The transcriber should be the model you dictate with. FluidAudio's own command-line tool, built from the package checkout, can do that.

## Experiment first

4. **A fully local cleanup that comes close to Cerebras.** Cerebras stays the default; the goal is a good offline option for the "Offline cleanup" Mode. The bar: Cerebras is 0.28 s median and 0.63 s at the 90th percentile (1,612 dictations since September), on top of about 0.09 s of transcription, with about 1 bad output in 60 in the November eval.

   Your stats show what one-shot local cleanup costs on this Mac (M4, 24 GB): VoiceInk Refine V1 averaged 0.73 s over 49 dictations, Gemma 3 4B 1.5 s, phi4-mini 1.0 s, against 0.43 s average for Cerebras. Small models (1 to 2B) are the only ones near the bar, so the two candidates are both that size:
   - **VoiceInk Refine V1**, upstream's local cleanup model (Qwen 3.5 based, 4-bit, 1 GB). Already downloaded and built into the Mode settings. Its quality was never graded.
   - **Phonon's refiner** (`Infatoshi/phonon-refiner-1.7b`, LFM3 1.7B, 988 MB GGUF). Trained on 76,960 dictation rewrites with self-correction and term fixes in the targets; free for personal use. It would run in `llama-server` or LM Studio if their llama.cpp supports the LFM3 architecture; the model card says it needs that, and the installed build (11960) is unverified. It would be set up in a Mode as a custom local provider with system instructions off. Its catch: it was trained on its own short system prompt, a writing-mode line, a `Vocabulary the speaker may use:` line, and the bare transcript, while VoiceInk wraps the transcript in `<TRANSCRIPT>` tags and adds its own vocabulary block. Whether that hurts is the first thing to test. Run it greedy (temperature 0); the GGUF's defaults are 0.1.

   **Result (2026-11-05): neither is close.** The 56 cases from the November eval, each request timed one at a time on this Mac, all outputs graded together blind against `checklist.md`:

   | Model | Median | 90th percentile | Bad outputs |
   |---|---|---|---|
   | Cerebras `qwen-3.8-27b`, System only (today's setup) | 0.29 s | 1.24 s | 9 of 168 (5%) |
   | VoiceInk Refine V1, MLX, as VoiceInk sends it | 0.37 s | 1.07 s | 55 of 168 (33%) |
   | Phonon refiner, llama.cpp, its trained prompt, minimal mode | 0.84 s | 1.69 s | 23 of 56 (41%) |
   | Phonon refiner, prompt mode | 0.87 s | 1.79 s | 24 of 56 (43%) |
   | Phonon refiner, as VoiceInk would send it | 1.01 s | 2.11 s | 24 of 56 (43%) |

   - VoiceInk Refine is close on speed but not on quality. It rewords ("gonna" to "going to", "temp" to "temperature"), drops "yeah" and "TBH", misses Dictionary words (Todoist, tirzepatide, ApoB), and wrote the email when asked to dictate "Write me a short email to Jeff…" (3 of 3 runs).
   - Phonon's refiner keeps wording better but ignores most of VoiceInk's spoken cues: "new line", "question mark", numbers as digits, spoken lists, and some self-corrections stay as said. Phonon trained it to a different target (it drops an opening "yeah" on purpose and keeps one paragraph in minimal mode). In llama.cpp it runs at about 75 tokens a second, so it is also the slowest here; Phonon's own engine is much faster.
   - Today's grader was stricter than November's (Cerebras 5% bad against about 2% then); the same grader graded every model, so the comparison holds.

   Cerebras stays. Re-test when a new small on-device cleanup model appears; a 26B-class local model (Gemma 4 26B-A4B, Qwen 3.8 27B) is too slow on this Mac to be practical. Raw results and grades are in `~/.local/state/evals/voiceink/cleanup-prompt/local/`. Run with `ENDPOINT=... LAYOUT=bare WORKERS=1` (see `run.py`).

5. **Try Phonon itself.** It is the other fully local option: a whole dictation app, not a model for VoiceInk. Its claim is about 30 ms from key-up to corrected text, against about 220 ms with its streaming off, both on an M4 Max; your M4 with 24 GB is above the 16 GB it needs for streaming cleanup. Install with its hotkey on Right Option so VoiceInk keeps fn. Two cautions: it downloads about 5 GB of models into `~/.cache/huggingface`, and it offers to quit VoiceInk because both default to fn. Remove it and its models afterwards unless you keep it.

6. **Vocabulary boosting inside Parakeet.** Phonon's best-measured accuracy win: steering the speech model's decoder toward dictionary terms cut dictionary-term misses from 72 to 54 and 90 to 63 on its author's dictations, with no change in overall error rate on 1,351 public clips. FluidAudio, VoiceInk's speech library, has its own version (a small CTC model rescores the output toward custom vocabulary; `CustomVocabulary/` in the package), and the CTC model is already on this Mac (`FluidAudio/Models/parakeet-ctc-110m-coreml`). VoiceInk does not use it for local models; it only sends vocabulary to Deepgram and ElevenLabs. Wiring it in is upstream-sized Swift, so the first step is a benchmark with FluidAudio's command-line tool on your own recordings and Dictionary, and an upstream feature request if it helps. Not before the vocabulary finder (3), because 41 terms is too few to measure.

7. **A chat style picked by app.** Phonon chooses a writing style from the app: casual (all lowercase except names and "I", no final period) in Messages, Discord, and WhatsApp; formal in Mail and Slack; prompt in AI apps, terminals, and editors; minimal elsewhere. You already have a Lowercase Mode you pick by hand. If you want it automatic in chat apps, add them to the Lowercase Mode's apps. That is a settings choice, not a measured win; Phonon has no number for it.

## Not for this fork

| Phonon feature | Why not |
|---|---|
| The refiner as a replacement for Cerebras | Expect it to be slower than Cerebras in VoiceInk's pipeline on this Mac (see 4); it is a candidate for the offline option only. Its own card shows no accuracy gain over Phonon's previous model on real dictation (-0.0017, interval includes zero) and a worse lecture score (8.5% vs 7.0% error rate). |
| Streaming cleanup, Metal kernels, speculative decoding, live text card | Architecture. Phonon turned live text off by default on 2026-11-05 because it was distracting. |
| Edit learning (watching the field after paste to learn terms) | VoiceInk has its own: auto-learn is on, with Cerebras reviewing. Phonon's version has no accuracy measurement. |
| Safety checks on cleanup output (fall back if the output is over 2x or under 0.4x the input, or only deleted a real word) | Would not have fired on your data: today's 11 cleanups stayed within 3 words of the input. Phonon has no measured win at its shipping model size. The meaning-only deletion rule ("an", "not" dropped) is the one worth adding as an eval case in `checklist.md` if it ever shows up. |
| Sending only matching dictionary terms to the cleanup model | Phonon's test was small (21 of 24 correct with the full list vs 22 of 24 without), and at 41 terms the full list costs nothing measurable (cleanup time did not change with prompt length in the November eval). |
| Screen text used only to confirm dictionary terms | VoiceInk pulls names from the screen into the vocabulary, but also sends the raw screen text to the cleanup model when a Mode has screen context on. Changing that is fork Swift for a small gain: Phonon's own estimate is that screen context is worth at most about half a point of error rate. |
| Bluetooth-headset mic skip, mic priority list | VoiceInk has a prioritized-device mode; you use a single fixed device. |
| Trailing space after paste, hold/tap/double-tap hotkey | Already in VoiceInk and on. |
| Backup mirror to `~/.phonon/backup` | VoiceInk has backup export. If a lost dictionary is a worry, a scheduled export is the simpler fix. |
| Competing-app detection, startup self-test, update check, recording cues, Windows build | No gain for a single-user fork. |

## How much to trust Phonon's numbers

The repo is careful: most claims quote paired confidence intervals and name their test sets. But the experiment log is private (`.gitignore` excludes `DEVLOG.md`; the checked-in one is a 12-line stub), the writing-mode spec is not checked in, and every speed number is from an M4 Max. Numbers above that come only from code comments or commit messages are stated as such. All the sample data is one person's dictation.
